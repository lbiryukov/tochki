# Точки

Браузерная игра «Точки» для двоих: на одном телефоне по очереди или по ссылке, каждый со своего телефона. Ставить ничего не нужно, это одна веб-страница.

- Сайт: https://lbiryukov.github.io/tochki/ (GitHub Pages, ветка `main`, корень репозитория)
- Игра по ссылке: Firebase Realtime Database + анонимный вход, проект `dots-5b009`, регион europe-west1
- Язык интерфейса и общения с владельцем: русский

## Правила игры (так реализовано и согласовано с владельцем)

- Поле 39×32 пересечения. Точки ставятся по очереди. Кто ходит первым, решает жребий.
- Окружение: цепочка своих точек, соседние стоят через одну клетку по горизонтали, вертикали или диагонали. Технически зона окружена, если из неё нельзя выйти к краю поля по 4 направлениям, не наступая на живые точки окружающего. Край поля окружением не считается.
- Очки дают только за захваченные точки соперника. Пустая обнесённая территория очков не даёт.
- Ставить точку внутрь зоны, окружённой соперником, нельзя, даже в пустой «домик». Поэтому ситуации «ход одновременно окружает и попадает в окружение» не бывает.
- Если окружить зону, где раньше захватили твои точки, они освобождаются (перезахват).
- Конец партии: нет ходов ни у кого, договорились (оба согласны на подсчёт) или кто-то сдался.
- Настройки выбирает создатель партии на экране «Новая партия»:
  - «Доп. ход за окружение»: окруживший точки соперника ходит ещё раз, цепочкой. По умолчанию выключено.
  - «Время на ход»: от 0:05 до 59:59, ввод в минутах и секундах. По умолчанию без ограничения. Не успел — ход пропускается и переходит сопернику (ход `-1` = PASS).
- В конце любой партии показывается статистика: ходов, в среднем и дольше всего думали, пропуски по времени. Пропуски в среднее не входят.
- В игре по ссылке отмены хода нет. Точка ставится в два касания: выбрать, затем подтвердить.

Решения владельца, которые не надо пересматривать без спроса: уведомления о ходе соперника (push, Telegram) не нужны. Ограничение времени — на ход, с пропуском, а не шахматные часы.

## Устройство

```
src/engine.js           игровой движок: чистый, детерминированный, UMD (window.DotsEngine / module.exports)
src/page.html           шаблон страницы: CSS + разметка + код интерфейса; метки <!--__BODY__-->, <!--__FIREBASE__-->, /*__ENGINE__*/
scripts/build.js        сборка: вставляет движок и Firebase, пишет index.html, dist/preview.html, mock/www/index.html
index.html              собранный сайт, который отдаёт Pages. Руками не править: менять src/, потом npm run build
firebase/database.rules.json   правила доступа к базе
test/engine.test.js     тесты движка, включая 104 случайные партии до конца
test/rules.test.js      тесты правил базы (targaryen)
mock/server.js          подменная база: хранит данные в памяти, каждую запись проверяет настоящими правилами, раздаёт изменения через SSE
mock/www/mock-firebase.js  заглушка Firebase compat SDK (то подмножество, которым пользуется страница)
test/e2e/*.py           сценарии на двух «телефонах» в Playwright против подменной базы
```

Главная идея: партия хранится как список ходов (`first`, `moves[]`, `end`, `opts`). Доска, захваты, очередь и счёт каждое устройство пересчитывает само через `E.replay`. Поэтому синхронизация простая, а повтор партии бесплатный. Движок не знает о времени. `opts.limit` он только хранит, а таймер, пропуски и статистика живут в интерфейсе.

### Данные в Realtime Database

```
keys/{room}/{0|1}                 ключи мест; пишутся один раз при создании, не читаются никем
members/{room}/{uid}/{seat}=key   устройство садится на место, если знает ключ; читает только свой uid
rooms/{room}/meta                 {w:39, h:32, first, created, v, bonus, limit}; пишется один раз
rooms/{room}/joined/{seat}, online/{seat}
rooms/{room}/started              серверное время, когда сел второй игрок (с него идёт отсчёт первого хода)
rooms/{room}/last                 серверное время последнего хода (от него считается дедлайн)
rooms/{room}/moves/{n}            индекс точки y*39+x или -1 (пропуск); только дописываются
rooms/{room}/times/{n}            серверное время хода n
rooms/{room}/agree/{seat}         предложение подсчёта: длина партии; отказ: -(len+1)
rooms/{room}/end                  {type:'resign', player} | {type:'agree'}
rooms/{room}/next                 {room, key} — реванш
```

- Ссылки: `#room/0/k0` у создателя, `#room/1/k1` у соперника, `#room` открывает партию зрителю. `k1 = SHA-256("tochki:room:k0:1")`, так создатель может снова показать ссылку для соперника.
- Ход отправляется одним `update`: `moves/n`, `times/n` и `last` с `ServerValue.TIMESTAMP`. Правила требуют `=== now` и не дают переписать ход.
- Пропуск (`-1`) правила разрешают, только если в партии есть лимит и прошло `last + limit − 2 с`. Пишет его телефон того, чей ход, ровно на дедлайне, или телефон соперника через 2,5 с после дедлайна, если первый спит. Гонки разрешает `!data.exists()` на `moves/n`.
- Порядок ходов правила не проверяют: клиенты доверяют друг другу. Игра для друзей, это осознанно.
- Часы клиента сверяются через `.info/serverTimeOffset`.

### Партия на одном телефоне

`localStorage`: `tochki.local.v1` (партия, её настройки и времена ходов), `tochki.setup.v1` (последние выбранные настройки), `tochki.rooms.v1` («Мои партии по ссылке», до 20 штук). Пока открыто меню, часы стоят. После перезагрузки отсчёт хода начинается заново.

### Внешний вид

Тетрадный лист в клетку и две шариковые ручки, красная и синяя. Шрифты Caveat (цифры, заголовки) и Golos Text (интерфейс). Все цвета — токены в `:root` с тёмной темой. Лист рисуется на canvas. В портретной ориентации поле повёрнуто, чтобы клетки были крупнее. Есть масштаб двумя пальцами и перемещение одним.

## Команды

```
npm install          # один раз: targaryen для тестов правил и подменной базы
npm test             # движок + правила базы
npm run build        # собрать index.html (и превью, и страницу для подменной базы)
npm run mock         # собрать и поднять подменную базу на http://localhost:8787/
npm run e2e          # сценарии в браузере; нужен Python и: pip install playwright && playwright install chromium
```

Перед любым коммитом: `npm test`, `npm run build`, и `npm run e2e`, если менялись интерфейс или синхронизация.

## Выкладка

1. Если менялись правила базы, выложить их **первыми**: Firebase Console → Realtime Database → Rules → вставить `firebase/database.rules.json` → Publish. Firebase CLI в проекте не настроен, владелец делает это вручную. Новые правила обязаны пропускать старый клиент, пока сайт не обновлён.
2. Закоммитить собранный `index.html` в `main`. Pages обновляется за 1–2 минуты, браузер может держать старую версию до 10 минут (помогает `?v=N` в адресе).

Обратная совместимость: в партиях, созданных старыми версиями, нет `times`/`started`, поэтому статистика там скрыта. Старые сохранения на телефоне без времён ходов тоже открываются, просто без статистики.

## Замечания

- Конфиг Firebase (`apiKey` и прочее) в `scripts/build.js` публичный по задумке. Предупреждение GitHub secret scanning о «Google API Key» закрывается как «won't fix». Ключ не отзывать, иначе сайт перестанет работать. По желанию его можно ограничить доменом `lbiryukov.github.io` в Google Cloud Console; пока не сделано.
- Облачная среда Claude не может достучаться до Firebase и gstatic, поэтому всё проверяется через подменную базу. Окончательная проверка — живая партия на двух телефонах.
- Превью для Claude (`dist/preview.html`) не содержит Firebase. В нём работает только игра на одном телефоне.
